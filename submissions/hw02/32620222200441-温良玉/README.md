## 二、来源证据卡

**来源：** UCI Machine Learning Repository，*Heart Disease* 数据集随附说明文件 `heart-disease.names`（数据集 DOI 10.24432/C52P4X，CC BY 4.0；数据页 https://archive.ics.uci.edu/dataset/45/heart+disease ）

**访问日期：** 2026-10-13

**原始说法：**
`heart-disease.names` 的变量条目第 58 条写：

> num: diagnosis of heart disease (angiographic disease status)
> -- Value 0: < 50% diameter narrowing
> -- Value 1: > 50% diameter narrowing

而同一份文件的 *Relevant Information* 一节又写：

> ...it is integer valued from 0 (no presence) to 4.

**用于核查的工作单证据编号：** B1（num 行的类型与角色）、B2（各中心原始结局的非空取值分布）

**核查结果和适用条件：**

同一份官方文件内部不一致：总说明给出 0–4 的取值域，详细条目只定义了 0 和 1，2、3、4 的判定标准在文件里找不到。工作单证据与这一矛盾吻合——表 B1 的 num 行同样只解释 0 与大于 0；表 B2 显示 Hungary 的 294 条记录只出现 0 和 1，而全表 2、3、4 档的 109、107、28 条全部来自另外三个中心，说明 0–4 这个取值域并不是四中心共同实现的，同一档在不同中心未必是同一个意思。

适用条件因此分两种：把 num 二分为"0"与"大于 0"**有官方依据，可以直接使用**；把 0–4 当作统一的递增疾病分期**没有依据**，只有当官方补出 2、3、4 各自的判定标准、并能证明四中心用的是同一套分级时才成立。

**修正后的说法：**

num 是造影疾病状态标签，可依官方说明派生为「无疾病（0）／有疾病（大于 0）」的二分类，用作卡方与二分类 Logistic 的结局。0–4 **不能**当作有序或等距的统一分期：既不能求平均、不能当连续结局入模，也不能在跨中心比较中直接使用。

（说明：原始说法这一栏是转述而非逐字引用，其中变量条目编号与文字以 UCI 官方文件为准；我核查的是"同一文件里总说明与详细条目是否一致"，这一点已由工作单表 B1、B2 独立验证。）

## 三、数据使用建议书

最终选项 C（限制使用）：保留四中心 920 条记录，但限定字段与中心的使用范围，不按原样合并。可描述对象是四中心的历史造影记录——编号只在中心内唯一，另有 2 条记录在 14 个临床字段上完全重复，故只能说"记录"、不能说"患者"。

字段上，age、thalach 为连续量，ca 为计数，cp、thal 等为类别，num 官方只定义 0 与大于 0；故分析问题定为"哪些特征与 num>0 有关联"，方法限卡方与二分类 Logistic，不把 0–4 当分期求平均。

质量证据：13 个特征共 1,759/11,960 个空缺（14.7%），胆固醇的 0 在 Switzerland 是整列 123/123，四中心阳性比例从 36.1% 到 93.5%。处理后果：删除全部缺失行后余 299 条，Cleveland 占 99.3%（原表 32.9%），"描述四中心患者"落空——这是不选 A、也不先清洗再建模的理由。

本表不能回答的新问题：随访。每行是一次检查的截面，缺观察时长与事件状态，分不清"观察到 12 个月仍未发生"与"确定没有发生"。

使用前须核查：取回四中心采集流程与入选标准，确认胆固醇、血压的 0 是未测还是实测；索取跨中心身份链接表，处理重复记录与独立性假设；取得四文件逐条数与合并规则，使 920 可复核。停止条件：完整病例中任一中心占比>80% 即不再代表四中心；零值性质未确认前，含 0 值的连续字段不进入标准化与跨中心比较；中心阳性率差异若无法用已记录变量解释，即停止合并建模。

## 四、AI 使用说明

**是否使用 AI：** 使用了（对话式 AI 助手），如实说明如下。

**AI 帮了哪些环节：**

1. **数值核对。** 各中心的缺失数与零值数、完整记录数、阳性比例、标准化 z 值等由 AI 按数据文件复算，我再与工作单表 C1、C2、D1、D2 的既有数字逐一对齐，不一致的地方以数据文件为准。
2. **文字整理。** 把我口语化的判断改写成工作单要求的条目式表述，不改变判断本身。
3. **指出我自己的表述漏洞。** 例如我原来写"num>0 的 0/1 平均值不能求"，AI 指出 R2 明确说 0/1 编码的均值就是"取值 1 的比例"，属于我理解有误，我据此改正。

**我如何核查 AI 的说法：**

- 凡是数字，都在 `heart-disease-four-site.csv` 里用独立方式重算一遍（如胆固醇零值按中心分组计数、cp 四类频数），只把能复算的数字写进作业。
- 凡是定义，回到一手来源比对：工作单表 B1、UCI 的变量条目原文、R1–R6 的原文。第二节的来源证据卡就是这么发现并记录矛盾的一次。
- 凡是从数据里判定不了的（缺失机制、测量误差、患者身份是否重复），一律写成"当前不可判定"或"待原始表确认"，不采信 AI 的推测。
- AI 给出的判断与证据冲突时，以证据为准，并把自己的错误留痕（见上面第 3 条）。
